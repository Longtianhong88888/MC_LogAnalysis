# 演讲提纲

## 汇报基本信息

- 汇报标题：MC Log Analysis 机台日志分析工具 · 使用说明
- 材料状态：有旧 PPT
- 汇报场景：新用户培训与日常使用参考（self-contained，无人讲解也能读懂）
- 听众画像：现场工程师 / 主管，中文环境
- 汇报时长：15-20 分钟（14 页）
- 总页数：14
- 证据密度：中（balanced_brief）

## 一句话主线

机台日志分析工具把"看日志、算 UPH/EFF、查报警、出报告"从手工变成一键完成——先让读者知道工具能解决什么问题，再教按 5 步完成一次分析，最后给制程口径、输出物与注意事项，保证读者能独立使用并读懂结果。

## 听众问题链

1. 听众第一个会问的问题：这工具能干什么、跟手工看日志有什么不同
2. 听众最容易质疑的地方：不同机台的 UPH 口径和计算逻辑是否靠谱
3. 听众需要被说服的关键点：一键分析确实能省时间、结果可信
4. 最后希望听众理解、决定或讨论什么：现在就可以打开工具，选日志→选制程→点自动报告，5 分钟拿到第一份报告

## 可能被问到的问题

- 问题 1：不同制程的 UPH 口径为什么不一样？
- 回答思路：各制程的机台结构、并行方式和瓶颈位置不同——LM 单机台只需摊换盘，CAW 双机台取瓶颈，FR 双轴并行需分别计算后加总。制程模板已按机台预配好这些逻辑。

- 问题 2：如果日志没有 status 行，状态分析还准吗？
- 回答思路：无 status 行时工具按活动关键词和停机关键词推导时间线，准确度取决于日志中关键词的覆盖程度。建议在 EReasonlist 中维护完整的停机关键词清单以提高准确度。

- 问题 3：分析结果能直接用于客户报告吗？
- 回答思路：Excel 和 PPT 都是可编辑的原生格式，时间格式已统一。建议复核 UPH 口径是否与客户定义一致（工具默认按 CoreTech AME 口径），必要时调整参数后重新生成。
